# expo-xcasset-plugin

An [Expo config plugin](https://docs.expo.dev/config-plugins/introduction/) that turns SVG files into iOS asset catalog (`xcassets`) vector images during `expo prebuild`.

iOS loads named images from the asset catalog (`UIImage(named:)`), and vector assets stay sharp at every scale. But the `ios/` folder is generated by prebuild, so you cannot add assets to it by hand. Point this plugin at your SVGs and it generates the image sets for you, with no Xcode involved.

## Install

```sh
npm install expo-xcasset-plugin
```

## Usage

Add the plugin to `app.json` with an array of `{ [assetName]: svgPath }` entries. Each path is relative to `app.json`.

```json
{
  "expo": {
    "plugins": [
      [
        "expo-xcasset-plugin",
        [
          { "tab-home": "./assets/icons/home.svg" },
          { "tab-cart": "./assets/icons/cart.svg" }
        ]
      ]
    ]
  }
}
```

Then generate the native project (or build with EAS) and use the asset by name. For example, with `expo-router` native tabs:

```tsx
import { NativeTabs } from 'expo-router/unstable-native-tabs';

<NativeTabs.Trigger name="cart">
  <NativeTabs.Trigger.Icon xcasset="tab-cart" />
</NativeTabs.Trigger>;
```

### Options

The plugin props are a list of `{ [assetName]: svgPath }` objects. An object may hold several entries, and a single object (`{ "tab-home": "./home.svg" }`) is accepted too.

| Part        | Rule                                                                                              |
| ----------- | ------------------------------------------------------------------------------------------------- |
| `assetName` | Letters, numbers, `-` and `_`, starting with a letter or number. Must be unique.                  |
| `svgPath`   | An `.svg` file, relative to the directory that holds `app.json`.                                  |

Invalid props fail as soon as the config is read, and a missing or unreadable SVG fails the prebuild with the asset name and the resolved path.

## What it generates

For each entry the plugin writes `Images.xcassets/<assetName>.imageset/` into the generated iOS project:

- `<assetName>.pdf`: the SVG converted to a single-page **vector** PDF (never rasterised), sized from the SVG's `width`/`height`, or its `viewBox` when there are none.
- `Contents.json`: marks the image as a vector (`preserves-vector-representation`) and as a **template** image (`template-rendering-intent`), so UIKit tints it, for example in tab bar items.

Running prebuild again replaces the image sets, and the output is identical between runs. Android and web are not touched.

## Good to know

- **Template rendering.** Images are tinted, so they suit single-colour icons. Multi-colour artwork would be drawn as its silhouette. `currentColor` (how icon libraries such as Hugeicons, Lucide or Feather ship their SVGs) is treated as black, which is fine because only the shape matters.
- **Supported SVG features** are those of [svg-to-pdfkit](https://github.com/alafr/SVG-to-PDFKit), which does the conversion. If an SVG produces nothing visible, the prebuild fails with an explanation instead of shipping a blank icon.
- **It needs a native build.** New assets are only in the app after `expo prebuild` / an EAS build; an over-the-air update cannot deliver them.
- **It expects the default Expo iOS project**, which contains `Images.xcassets`.
- Tested with Expo SDK 57.

## Development

```sh
npm install
npm test     # builds, then runs the tests with Node's test runner
```

The tests run the plugin through Expo's own mod compiler against a generated iOS project, the same way `expo prebuild` invokes it.
